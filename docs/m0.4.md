# Raz 2 — M0.4

M0.4 adds the first compiler-level Core facilities. They are intentionally small and AST-based so the language can grow without turning into a textual preprocessor.

## Core directives

`__phead("...");` injects trusted preprocessor/C++ header text into the generated C++ prelude. Duplicate directives with the exact same text are emitted once.

`__eval("...");` injects trusted native C++ at the point where it appears. Inside a function it is emitted as function-body code. A top-level `__eval` is allowed only in the root source file during bootstrap.

## Macros

Macros are declared at module scope:

```raz
macro twice(x) {
    return x + x;
}

macro say(x) {
    echo(x);
}
```

An expression macro is exactly one `return expression;`. It can be used inside expressions:

```raz
let answer = twice(21);
```

A statement macro contains only expression statements and Core directives:

```raz
say("hello");
```

Macros expand at the AST level before semantic analysis. Arguments are therefore type-checked after expansion using the normal M0.3 analyzer.

Macros can live in imported modules and can be called as `module::macro(...)`. Unqualified ordinary function calls inside an imported macro body are preserved against accidental caller-scope capture by qualifying them with the defining module.

## Deliberate limits

M0.4 macros do not yet support local variable declarations, loops, or arbitrary nested control flow inside macro bodies. This avoids introducing macro hygiene rules before the Core model is defined. Recursive macro expansion is rejected.
