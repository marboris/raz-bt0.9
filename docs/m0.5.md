# Raz 2 — M0.5

M0.5 introduces the first real asynchronous execution model.

## Async functions

Declare an asynchronous function with `async function`:

```raz
async function delayed_double(x: int) -> int {
    sleep(1);
    return x * 2;
}
```

The Raz function keeps its logical return type (`int` here), but the generated C++ function returns `std::future<int>`.

## Await

`await` unwraps an async task inside a function:

```raz
async function combined(x: int) -> int {
    let left = await delayed_double(x);
    let right = await delayed_double(1);
    return left + right;
}

function main() {
    echo(await combined(20));
}
```

`await` is only legal inside a function and requires an async task/future expression.

## Fire-and-forget

A call to an async function used as a standalone statement is automatically retained by the generated runtime:

```raz
function main() {
    delayed_double(100);
}
```

The runtime keeps the future alive and waits for retained tasks during process shutdown. This implements the original Raz design goal that an un-awaited async task should not be silently destroyed when the main function returns.

## Runtime

The generated C++ contains a small runtime namespace with:

- `raz::sleep(int)`
- `raz::spawn(std::future<T>)`
- `raz::AsyncRegistry`, which retains detached futures and waits on shutdown

M0.5 intentionally uses `std::async(std::launch::async)` rather than a custom thread pool or coroutine scheduler. The historical thread-pool/coroutine experiments from the original Raz/Marboris archives can become later runtime backends without changing the surface language.
